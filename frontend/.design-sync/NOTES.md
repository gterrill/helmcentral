# design-sync notes — helmcentral-dashboard

## Repo shape

- No Storybook, no publishable library build (`package.json` has no `module`/`main`/`exports`) — this is an app, not a component package. Synth-entry mode reads directly from `src/components/**` (`cfg.srcDir`).
- Self-referencing symlink required for synth-entry mode to resolve `PKG_DIR`: `node_modules/helmcentral-dashboard -> ..` (created once; gitignored via the existing `node_modules/` rule, recreate on a fresh clone with `cd node_modules && ln -sfn .. helmcentral-dashboard`).
- Scope is deliberately **all of `src/components/**`** (14 shadcn/Base UI primitives + their compound subparts, plus ~28 marine-dashboard-specific tiles/drawers) — 113 components total, not the ~42 originally estimated. The user chose "ui + dashboard tiles" scope explicitly, overriding the recommendation to sync only `components/ui/`.
- `AdminPage` (from `caches-page.tsx`) is excluded via `componentSrcMap: {"AdminPage": null}` — it's a full route/page, not a reusable component.
- Preview-authoring scope: the 14 `components/ui/` primitives + their compound subparts (~79 components) get authored rich previews. The ~34 dashboard tiles ship as floor cards (functional, unstyled-preview) for now — authorable on a future re-sync.
- Grouping: everything currently lands under a single `general` group (both `ui/` and the repo root are in the heuristic's `GENERIC_DIR` skip-list, so no subdirectory signal survives). Not fixed — cosmetic, not blocking. A future pass could set per-component groups via `docsMap` stub files with `category` frontmatter if the flat list becomes hard to browse in the DS pane.

## Fixes applied

- **`import.meta.glob` crash (critical, blocked ALL 113 components)**: `src/config/app-config.ts` called `import.meta.glob(..., {eager: true})` at module top level to read `settings.yaml`. Vite transforms this at its own build time; plain esbuild (what design-sync uses) leaves it as a real function call → `TypeError: import_meta.glob is not a function` the instant the module loads. It's reached transitively via `src/hooks/use-vessel-identity.ts` (imported by `marine-header.tsx` and `vessel-status-bar.tsx`), which did a **value** import of `uiConfig`. Since synth-entry mode bundles all of `src/components/**` into one shared IIFE, this one eager crash took down the entire bundle for every component, not just those two.
  - Fix: made `uiConfig`/`anchorConfig` lazy memoized getters (`getUiConfig()`/`getAnchorConfig()`) instead of eager top-level consts. Updated call sites in `src/App.tsx` and `src/hooks/use-vessel-identity.ts`, and the 5 test files that mock `@/config/app-config` (`app-sidebar-navigation.test.tsx`, `App.smoke.test.tsx`, `anchor-watch-drawer-drop.test.tsx`, `anchor-imagery-toggle.test.tsx`, `time-to-go-zero.test.tsx`). Full test suite (200 tests) + `tsc --noEmit` pass after the change.
  - Other files doing `import type { X } from '@/config/app-config'` (today-now-tile, nearby-vessels-tile, rode-scope-tile) were never the problem — type-only imports are erased entirely and were red herrings during diagnosis.
- **All previews rendered unstyled (browser-default buttons, no rounded corners/colors)**: `cfg.cssEntry` originally pointed at `src/index.css`, which is raw `@tailwind base/components/utilities` — unprocessed source, not real CSS. design-sync copies the file as-is; it doesn't run PostCSS/Tailwind. Fixed by pointing `cssEntry` at a real compiled stylesheet instead.
  - Since `vite build`'s output CSS filename is content-hashed (changes every build), `cfg.buildCmd` runs the build AND copies the hashed CSS to a stable path: `npx vite build && mkdir -p .design-sync/.cache/build && cp dist/assets/index-*.css .design-sync/.cache/build/styles.css`. `cssEntry` points at that stable copy. **Always re-run `cfg.buildCmd` before a rebuild** if you suspect the CSS is stale — the stable copy does not update itself.
- `[FONT_MISSING]` for Geist Sans/Mono: wired via `cfg.extraFonts` pointing at `node_modules/@fontsource/geist-{sans,mono}/{400,500,600,700}.css` (matches the weights actually imported in `src/main.tsx`).

## Preview-authoring batch notes

- **Breadcrumb subparts** (`BreadcrumbList`, `BreadcrumbItem`, `BreadcrumbLink`, `BreadcrumbPage`, `BreadcrumbSeparator`, `BreadcrumbEllipsis`) don't crash standalone but render as meaningless unstyled fragments without the full `<Breadcrumb><BreadcrumbList>...</BreadcrumbList></Breadcrumb>` wrapper — every subpart's preview composes the full trail context. No config changes needed.
- **`Tile`** (`src/components/ui/tile.tsx`) is a plain prop-driven wrapper around `Card`, no provider needed. Its title-icon slot is deliberately tiny (`h-3.5 w-3.5`) — icons render small/subtle next to the uppercase tracked-out title by design, not a bug.
- **Popover (Base UI `@base-ui/react/popover`) portals render fine in the default grid card mode** — no `cfg.overrides.<Name>: {"cardMode": "single"}` needed despite `PopoverContent` going through a Portal. Use `defaultOpen` (uncontrolled) on the root to force it open for a static preview — `open` alone needs a controlled `onOpenChange` handler. Not yet confirmed whether this generalizes to other portal components (Dialog/Sheet, Tooltip) — check card overflow on those independently rather than assuming.
- **Emoji/color-glyph children inside a Base UI `render` prop can render as a tiny unstyled fallback in headless-Chromium capture** (seen on an icon-only `PopoverTrigger` with an emoji child). Not isolated as a real Base UI prop-merging bug — plain-text children render fine. If an icon-only trigger preview is needed, check headless Chromium's emoji font support first rather than assuming it's a composition mistake.
- **Base UI uses `render={<Element/>}`, not Radix's `asChild`.** E.g. `<SheetTrigger render={<Button variant="outline">Open</Button>} />`. Passing `asChild` does nothing useful (forwarded as an unknown DOM attribute) — the trigger renders its own default element instead of merging, producing double buttons/broken semantics if not caught.
- **Static-open overlay previews need different prop combos per family**: `Tooltip` needs `defaultOpen` AND `defaultTriggerId` (matching the `TooltipTrigger`'s `id`) — `defaultOpen` alone doesn't associate it with a trigger for positioning. `Select` needs `defaultValue` + `defaultOpen`. `Sheet`/dialog only needs `defaultOpen` alone. Popover only needs `defaultOpen` (see above).
- **`Button` has no `destructive` variant** (only `default | secondary | outline | ghost`) even though `--destructive`/`--destructive-foreground` tokens exist in `src/index.css`/`tailwind.config.ts`. For destructive actions, apply `className="bg-destructive text-destructive-foreground hover:bg-destructive/90"` directly rather than inventing a nonexistent variant.
- **Icons come from `lucide-react` directly** in previews, not re-exported through `helmcentral-dashboard`.
- **`SheetPortal` (Base UI `Dialog.Portal`) has no independent visual** — pure structural teleport wrapper. Compose its preview as a full open Sheet, same as the `Sheet` story.
- **All 23 `Sidebar*` parts hinge on `SidebarContext`/`useSidebar()`** — every subpart except `SidebarProvider` throws without a `SidebarProvider > Sidebar` ancestor. Default `Sidebar` (`collapsible="offcanvas"`) renders behind `hidden md:block`/`md:flex` responsive classes and measures via `matchMedia` — risks an empty/zero-height capture. Use `collapsible="none"` on the shell `<Sidebar>` for reliable full-content previews unless the story is specifically about the collapsed/icon state (`SidebarProvider`'s `CollapsedIcon` story uses `collapsible="icon"`; `SidebarRail` needs `collapsible="offcanvas"` since its hover styling depends on `data-side`/`data-collapsible` attrs only present there; `SidebarInset` uses `variant="inset"` on `Sidebar`).
- **`cardMode` overrides applied after the full-bundle render check** (per-component scoped captures during batch authoring don't catch grid-presentation issues — only the full `package-validate.mjs` run does): `column` for `Card`/`CardAction`/`CardFooter` (render too wide for a default cell) and for the Sidebar family (already set); `single` + `primaryStory` for every portal/overlay component whose content escapes the grid regardless of column/row width: `Popover`, `PopoverContent`, the `Select*` family, the `Sheet*` family, `Tooltip*` family, plus `SidebarProvider` (its `CollapsedIcon` story specifically) and `SidebarRail` (`RailAtEdge`) — these were switched from `column` to `single` since column mode does NOT fix portal escapes, only `single` does.

## Known render warns (re-syncs: check new warns against this list before chasing them)

- `[RENDER_THIN] ... rendered height is 0px` on `SheetClose`, `SheetContent`, `SheetDescription`, `SheetFooter`, `SheetHeader`, `SheetOverlay`, `SheetTitle` — all confirmed benign by inspecting the actual screenshots (`ds-bundle/_screenshots/general__<Name>.png`): each shows a fully real, styled, open Sheet dialog with correct content. The height-detection heuristic gets confused by the Sheet's portal structure (root measured has 0 height while the actual visible content lives in a portaled sibling appended elsewhere in the DOM) — a measurement artifact, not a rendering failure.

## Re-sync risks (read this before a future re-sync)

- If `src/config/app-config.ts` (or anything else with a Vite-only top-level side effect: `import.meta.glob`, `import.meta.env` beyond what's defined, etc.) gains a new transitive importer from `src/components/**`, the whole bundle can silently break again the same way. There's no automated guard for this — if `package-validate.mjs` reports `[BUNDLE_EXPORT]` with 100% of components missing, or every component shows the same `RENDER_ERRORS`, suspect a top-level eager crash in a shared import, not a per-component issue.
- The `.design-sync/.cache/build/styles.css` stable-path copy is machine state, not tracked by git (`.design-sync/.cache/` is gitignored) — a fresh clone must run `cfg.buildCmd` (or just `npx vite build` + the copy step) before the first `package-build.mjs` run, or `cssEntry` will 404.
- The `node_modules/helmcentral-dashboard` self-symlink is also machine state (inside gitignored `node_modules/`) — recreate it on every fresh clone/CI run before invoking the converter.
- Preview-authoring scope (79 primitives authored, 34 tiles left as floor cards) was a judgment call, not a technical constraint — if the user wants the dashboard tiles authored too, that's a straightforward future re-sync, not a re-architecture.
